# Senior SA Operating Model

## Core chain

Customer statement  
→ underlying problem  
→ business consequence  
→ desired outcome  
→ measurable success  
→ functional/NFR requirements  
→ architecture choice  
→ Databricks capability  
→ implementation/prototype  
→ validation  
→ next business decision

## Principles

### Problem before product
Do not begin with a list of Databricks capabilities.

### Validate before designing
Use discovery to resolve uncertainties that materially affect architecture or value.

### Architecture is broader than Databricks
Always show what remains outside Databricks and how the solution integrates with the wider cloud and enterprise estate.

### Separate prototype from production
A prototype demonstrates a hypothesis. Production design must address security, scale, operability, cost, recovery, CI/CD, and ownership.

### Translate constantly
An SA should be able to explain the same design to:
- a business leader
- a data leader
- an enterprise architect
- security
- finance/FinOps
- engineers

### Progress the engagement
Every substantial customer interaction should end with a clear next decision, proof point, owner, or action.
