# Value Mapping

## Goal
Connect technical decisions to customer value without inventing ROI.

## Core chain
Customer statement → problem → consequence → required capability → architecture decision → Databricks capability → business outcome → metric.

## Workflow
1. Preserve the customer's language.
2. Identify the underlying problem.
3. Translate it into revenue, cost, risk, productivity, experience, or resilience.
4. Define the capability required before choosing products.
5. Map to architecture.
6. Select Databricks capabilities only where justified.
7. Define measurable proof.
8. Separate known value from hypotheses requiring validation.

## Guardrails
- Never start with “Databricks has...”.
- Do not invent financial impact.
- Avoid generic “single platform” claims unless fragmentation is actually a customer problem.
- Do not force replacement of existing platforms.

## Output
A value map with:
- customer statement
- problem
- business consequence
- required capability
- architecture decision
- Databricks capability
- business outcome
- metric/proof point
