# SA Engagement Orchestrator

## Goal
Choose the right SA workflow for the current customer-engagement stage and coordinate focused specialist skills.

## Engagement stages
Identify which stage applies:
- initial discovery
- qualification / technical discovery
- architecture workshop
- technical deep dive
- prototype / Build & Demo
- security review
- cost / FinOps review
- PoC planning or playback
- production-readiness review
- executive playback

## Workflow
1. Identify the desired customer decision or outcome.
2. Identify personas and stakeholders.
3. Summarize known context and unresolved assumptions.
4. Select only the specialist skills needed.
5. Sequence the engagement from problem to next decision.
6. Keep Databricks positioning tied to customer requirements.
7. End with explicit owners, evidence required, and next steps.

## Common skill routing
- ambiguous customer problem → `customer-discovery`
- quantify value → `value-mapping`
- meeting preparation → `customer-meeting`
- target design → `solution-architecture`
- security concerns → `security-governance-review`
- cloud connectivity → `cloud-networking-review`
- prototype scope → `prototype-planner`
- customer-facing demo → `demo-storytelling`
- stakeholder challenge → `persona-objection-handling`
- PoC → `poc-design`
- production gate → `production-readiness-review`

## Guardrails
- Do not invoke every skill automatically.
- Do not force a prototype when discovery is incomplete.
- Do not turn the engagement into a Databricks feature tour.
- Do not treat the interview as the default context; treat Build & Demo as one engagement mode.

## Output
1. engagement stage
2. desired outcome
3. persona map
4. assumptions
5. skill sequence
6. meeting/delivery plan
7. next decision
